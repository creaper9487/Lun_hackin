## 這是什麼

Chrome 的 scroll-triggered animations 讓你用純 CSS 做「捲到某個位置才開始播放」的動畫。以前這類效果幾乎都靠 IntersectionObserver 加 class，現在宣告一個 trigger，再告訴動畫「啟動時往前播、離開時倒著播」就好。靈感來自 Chrome 開發者部落格的 [Scroll-triggered animations](https://developer.chrome.com/blog/scroll-triggered-animations) 一文。

和我們熟悉的 scroll-driven animations 不同，後者的進度綁在捲動位置上，前者只是在某個捲動點「按下播放鍵」，動畫自己用時間跑完。

## 怎麼做的

核心只有三行：

```css
.st-card {
  timeline-trigger: --t view() contain 0% contain 100% / entry 100% exit 0%;
  trigger-scope: --t;
  animation: st-in 0.5s ease-out both;
  animation-trigger: --t play-forwards play-backwards;
}
```

`timeline-trigger` 定義一個叫 `--t` 的觸發器，來源是這個元素自己的 `view()` 時間軸。斜線前是啟動範圍，斜線後是作用範圍，規格要求作用範圍必須包住啟動範圍。`animation-trigger` 則指定啟動時 `play-forwards`、停用時 `play-backwards`。

因為 trigger 名稱是全域的，同一條規則會匹配很多張卡片，所以要加 `trigger-scope: --t`，讓每張卡片各用各的，不然只有最後一張會生效。

## 瀏覽器支援與 fallback

目前只有 Chromium 系列（文章標示 Chrome 145 起）支援。Demo 用 `@supports (timeline-trigger: --t view())` 包住原生寫法，不支援時 script 會改用 IntersectionObserver 切換 class，效果相同，只是多了 JS。同時尊重 `prefers-reduced-motion`：偏好減少動態時，原生動畫不會啟用。

## 踩到的坑與下次想試

- 範圍的寫法要花點時間理解，`contain` 與 `cover` 的百分比對照得慢慢試。
- 全域 trigger 名稱很容易踩雷，記得 `trigger-scope`。
- 這次我沒有在多款瀏覽器實測，只確認建置通過，原生效果的細節以 Chrome 為準。
- 下次想試試把 trigger 放在一個元素、動畫套在另一個元素上，做出「捲到章節標題，旁邊圖表才動」的效果。
